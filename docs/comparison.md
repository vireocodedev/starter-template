# Evaluation and comparison boundaries

Vireo is for teams that want a conventional React PWA and Spring Boot service with a curated integration baseline and app-owned source. Evaluate that trade before comparing feature counts.

| Starting point | Strong reason to choose it | What Vireo is trying to prove instead |
| --- | --- | --- |
| Manual React + Spring Boot assembly | Maximum library and architecture freedom with no framework-specific conventions | A reviewed baseline can remove repeated integration work while leaving ordinary app code and explicit seams |
| [Hilla](https://vaadin.com/hilla) | A tightly integrated Java-to-React stack with generated browser-callable services and types | Conventional HTTP/service boundaries, MUI/TanStack composition, and selective subsystem adoption |
| [JHipster](https://www.jhipster.tech/) | Broad application generation, deployment options, and a large blueprint/module ecosystem | A smaller golden path with narrow generation, deeper UI-state contracts, and less generated surface |
| [Refine](https://refine.dev/) or [React-admin](https://marmelab.com/react-admin/) | Mature frontend-first data/admin abstractions and provider ecosystems | A coordinated React + Spring baseline including backend contracts, migrations, authentication, and operations guidance |

This table is a selection boundary, not a benchmark result. Vireo does not claim broader generation than JHipster, tighter Java/TypeScript integration than Hilla, a larger frontend ecosystem than Refine/react-admin, or more freedom than assembling the stack manually. Re-run the official quickstarts for any comparison used in public marketing; the repository's earlier desk research is not permanent competitive proof.

Choose Vireo only if the [flagship path](flagship.md), [public API map](https://github.com/vireocodedev/starter/blob/main/docs/PUBLIC_API.md), and [evaluation limits](https://github.com/vireocodedev/starter/blob/main/docs/EVALUATION.md) match the application you intend to own.
